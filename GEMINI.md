# Project Workflow & Implementation Rules

All AI assistants working on this project must strictly adhere to the following workflow rules at all times:

## 1. Mandatory Pre-Implementation Approval
- **Never modify or create code without explicit user approval.**
- Before writing any code, modifying files, or executing mutating commands, you must propose your implementation plan/approach to the user.
- Explicitly ask for and wait for user confirmation before starting implementation.

## 2. Phased & Bite-Sized Incremental Development
- **Deconstruct any large or non-trivial unit of code into small, sequential phases.**
- Each phase must be small enough to be easily reviewed and understood.
- Implement strictly **one phase at a time**.
- Do not proceed to subsequent phases until the current phase is completed, reviewed, and approved by the user.

## 3. Post-Implementation Explanation & Architectural Rationale
- After implementing each approved phase, provide a concise post-implementation walkthrough containing:
  1. **Line-by-line / block explanation**: Concisely explain what each line or block of the newly introduced or modified code does.
  2. **Approach rationale & alternatives**: Clearly explain **why** this specific approach was selected and why alternative approaches were not chosen (covering trade-offs, maintainability, architectural fit, performance, and best practices).
- Ask for user review and approval of the completed phase before proceeding to the next phase.
